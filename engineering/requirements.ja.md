# 要件 — arkham

実行可能な日本語要約です。完全版は[英語仕様](requirements.en.md)、既存の根拠は[公開アーキテクチャ](../docs/architecture.ja.md)です。以下は提案仕様であり、公開アプリや実行済み検証を示しません。

目的は、サーバーが決めた拠点の募集を案内し、適格性と書類メタデータを確認して、明確にシミュレーションと示した受付結果を返すことです。GPSは振り分けの入力であり、本人確認、住所、就労資格の証明ではありません。

| ID | 提案する受入条件 |
| --- | --- |
| A01 | 募集一覧の前にセッションを要求し、版管理した方針で`base_code`を決定する。未認証・期限切れ401、対象外403、形式不正422。 |
| A02 | セッション内で拠点を変更しない。クライアント指定拠点を権限として使わない。変更要求は409と明示的な再開始。 |
| A03 | 緯度−90..90、経度−180..180、正の精度値を確認する。位置取得拒否時に再試行を案内し、既定拠点を黙って選ばない。 |
| A04 | 版管理した規則で`eligible`、`ineligible`、`unknown`と理由を返す。未回答を偽とせず、unknownでは次へ進めない。 |
| A05 | 募集・書類区分を同じ拠点とカタログ版に結び、送信時に再確認する。終了・版変更は409と再検索。 |
| A06 | 架空メタデータのみ。デモ案は各10 MiB以下、PDF/JPEG/PNG、必須区分を重複なく揃える。不正は422。 |
| A07 | 同一オリジン、有効セッション、最新の適格結果、冪等キーを要求する。オリジン403、前提不成立409。本物の受領は503で停止。 |
| A08 | `simulation_only: true`を返す。同一キー・同一内容は同一受付結果、内容変更は409。 |
| A09 | ログは理由コード・版・相関参照に限定し、座標、書類内容、回答を含めない。 |

画面は拠点・理由・シミュレーション表示を示し、再読込はサーバー状態から復元します。取消時はセッション無効化と一時下書き削除を行う設計です。実装前に、境界、位置精度、期限、適格規則、必須書類、保持期間の承認が必要です。10 MiBとMIME一覧は架空デモ向けの設計判断で、運用済み方針ではありません。技術スタックや地図サービスは未選定です。
