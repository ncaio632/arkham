# モジュールと状態 — arkham

[英語完全版](architecture.en.md)の実装向け要約です。以下は論理責務で、稼働中のサービスを示しません。初期実装は単一プロセスでも構いません。

| モジュール | 責務と制約 |
| --- | --- |
| 位置入力 | 一時的な座標と精度を検証し、生座標を記録しない。 |
| セッション範囲 | セッション生成・失効、固定拠点、期限、版を所有する。 |
| 募集カタログ | セッション拠点だけで募集・書類区分を検索する。 |
| 適格評価 | 明示回答と規則版から三値判定する。送信や拠点変更はしない。 |
| メタデータ検査 | 区分・MIME・サイズのみを検証し、実ファイルを受け取らない。 |
| 申請調整 | 認可とシミュレーション結果を原子的に処理する。実受領は停止する。 |
| 画面 | 状態と復旧手順を表示し、画面の手順番号を権限にしない。 |

遷移は`unbound → scoped → assessing → ready → simulated`です。適格外・不明は`blocked`となり、明示的な回答修正で`assessing`へ戻します。募集・規則版が変わった`ready`も再評価します。有効状態は期限切れ・取消可能で、取消はセッションを失効させます。`expired`は新規セッションが必要です。同一拠点で募集を変えると評価と書類準備を消し、拠点変更は新規開始にします。

[Schema](../contracts/onboarding-snapshot.schema.json)は架空の内部スナップショットであり、既存セッション要求や全項目のクライアント更新用ではありません。提案コマンドは`startSession`、`selectOpportunity`、`evaluateEligibility`、`validateMetadata`、`simulateApplication`、`cancelSession`です。変更時は期待版を照合して`revision`を増やし、競合409では再取得します。

Schemaは拠点設定済みセッションを表し、`unbound`は含みません。送信時はオリジンと有効セッションを確認後、既存キーを検索します。同一内容の再試行は旧期待版の比較前に保存結果を返し、内容変更は競合にします。新規キーには現行版照合が必要です。申請時の版比較と結果作成は同一トランザクションまたは条件付き書込で行います。セッション単位の冪等キーに募集版とメタデータ指紋を固定し、別キーでも同一選択を重複作成しません。認可、期限、拠点一致、規則の鮮度、区分網羅はSchema外の意味検証です。

エラーは`code`、`retryable`、`correlation_ref`と安全な項目パスを返します。例は`SESSION_EXPIRED`、`BASE_CONFLICT`、`ELIGIBILITY_UNKNOWN`、`CATALOG_CHANGED`です。同一オリジン確認は認可の代用ではありません。実公開前にCookie、CSRF、永続化の設計確認が必要です。
