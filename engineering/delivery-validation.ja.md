# バックログと検証対応 — arkham

[英語完全版](delivery-validation.en.md)の要約です。製品検証はすべて**計画であり未実行**です。[役割仕様](../agents/session-scope-steward.md)は手動の分担を定め、自動呼出しは行いません。

| 順序 | 作業と受入条件 |
| --- | --- |
| B1 | 架空の振分け・期限・適格・書類方針を版管理し、未回答と否定を区別する。未決の運用方針に所有者を付ける。 |
| B2、B1後 | 入力検証、拠点固定、期限切れ拒否、再開始時の失効を実装し、生位置ログを排除する。 |
| B3、B2後 | 拠点限定カタログ、三値評価、募集変更時の依存状態リセットを実装する。 |
| B4、B3後 | メタデータ検証、利用可能な復旧表示、サーバーからの再読込を実装する。 |
| B5、B4後 | 書込時のオリジン・版確認、原子性、重複防止、実受領停止を実装する。 |
| B6、B5後 | 架空手順を実行し、観測値と失敗を記録し、独立レビューする。 |

| 要件 | 計画する検証 |
| --- | --- |
| A01 | セッションなし・期限切れ・対象外で一覧と受付結果を返さない。 |
| A02 | 拠点・募集の改変と同時要求でAを維持しB情報を返さない。 |
| A03 | 座標境界、位置拒否、非正の精度を明示的に拒否する。 |
| A04 | true/false/欠落と規則変更で三値を保ち、不明をreadyにしない。 |
| A05 | 募集終了・版変更時は409で書き込まない。 |
| A06 | 10 MiBと超過、区分欠落・重複を試す。 |
| A07 | 禁止オリジン・旧版・実モードで403/409/503、変更なし。 |
| A08 | 同時キー、内容変更、別キーで結果1件と必要な競合を確認する。 |
| A09 | ログとエラーから座標・回答・書類内容を除く。 |

[正常例](../examples/snapshot.valid.json)は架空です。[構造不正例](../examples/snapshot.invalid-schema.json)は`documents[0].size_bytes`で上限超過します。[意味不正例](../examples/snapshot.invalid-semantic.json)は[Schema](../contracts/onboarding-snapshot.schema.json)を通りますが、AセッションでB募集を選んでいるため`BASE_CONFLICT`が必要です。

Draft 2020-12で検証してください。JSON解析だけでは不足です。拠点一致、現在時刻、外部カタログの区分、認可は別の意味検証で扱います。識別子パターンは公開架空例専用で、セキュリティ機構ではありません。将来の証跡は試験ID、要件ID、実装版、入力版、環境、期待値、観測値、判定、レビュアーを含め、`not_run/pass/fail/blocked`を明示します。本番適性は別の方針・脅威・アクセシビリティ・運用審査まで未決です。
